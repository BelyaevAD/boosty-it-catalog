# Сопровождение Boosty IT Каталога

Этот документ предназначен для разработчиков и сопровождающих проекта. Пользовательское описание каталога находится в [README](../README.md).

## Структура данных

- [`data/channels.json`](../data/channels.json) — очищенный публичный каталог; `category` хранит основную тему, а `topics` — все подходящие темы канала;
- [`data/raw/boosty-candidates.json`](../data/raw/boosty-candidates.json) — полный список найденных кандидатов до тематической фильтрации;
- [`data/manual-exclusions.json`](../data/manual-exclusions.json) — проверенные вручную ложные совпадения;
- [`data/history/`](../data/history/) — датированные снимки показателей;
- [`data/latest-update.json`](../data/latest-update.json) — отчёт последнего обновления и состояние очереди повторной проверки.

На публичный сайт не попадают поисковые запросы, собранные внешние ссылки авторов и внутренняя методика исследования.

## Автоматические процессы

В репозитории работают три GitHub Actions workflow:

- `CI` проверяет данные, тесты и статическую сборку при изменениях в `main` и pull request;
- `Weekly data refresh` запускается каждую пятницу в 17:00 по Москве, обновляет публичные сведения, повторно валидирует каталог и фиксирует только проверенные изменения в `data/`;
- `Deploy GitHub Pages` собирает сайт, загружает Pages-артефакт и публикует его после подходящих изменений или успешного обновления данных.

Обновления GitHub Actions предлагает Dependabot. Сторонние actions закрепляются полными commit SHA, права workflow ограничиваются необходимым минимумом, а установка npm-пакетов выполняется через lockfile с отключёнными lifecycle scripts.

## Публикуемые артефакты и внешние обращения

Статическая сборка создаёт основную страницу каталога, индексируемые страницы каналов, sitemap, RSS и структурированные данные Schema.org.

Основная страница не устанавливает cookies и не использует собственную аналитику. Стандартный GitHub Star widget изолирован в sandboxed iframe и не подключает свой JavaScript к основной странице. При загрузке живого счётчика браузер обращается к `ghbtns.com` и `api.github.com`; эти сервисы получают обычные сетевые данные, включая IP-адрес и User-Agent.

## Ручной запуск обновления

1. Откройте вкладку **Actions** в GitHub.
2. Выберите **Weekly data refresh**.
3. Нажмите **Run workflow** для ветки `main`.
4. Дождитесь успешного завершения заданий `refresh` и `commit`.
5. Проверьте следующий запуск **Deploy GitHub Pages** и отчёт в [`data/latest-update.json`](../data/latest-update.json).

Ручной запуск использует тот же процесс проверки, что и еженедельное расписание, и может создать новый commit с обновлёнными данными.

## Локальная проверка

Нужен Node.js 20 или новее.

```bash
npm ci
npm run check
npx serve dist
```

Команда `npm run check` последовательно проверяет данные, запускает тесты, собирает сайт в `dist/` и валидирует результат. В проекте нет runtime-зависимостей; `npx serve` нужен только для локального просмотра.

## Требования к данным

Канал может попасть в публичный каталог, если:

- основная аудитория и материалы русскоязычные;
- тематика относится к IT или близкой цифровой практике;
- существует хотя бы один платный уровень;
- есть хотя бы одна публикация;
- публичная страница доступна и не заблокирована.

Основная тема сохраняется в `category`, дополнительные подходящие направления — в `topics`. Один канал может участвовать сразу в нескольких тематических фильтрах.

Перед публикацией описания очищаются от явных e-mail, телефонных и платёжных номеров, мессенджер-ссылок, контактных `@handle` и прямых инструкций связаться. Имена авторов и названия брендов сохраняются.

Не добавляйте в репозиторий cookies, токены, закрытые материалы, приватные контактные данные или необработанные артефакты авторизованного браузера.

## Проверка после изменений

Перед отправкой изменений:

1. выполните `npm run check`;
2. убедитесь, что `git diff --check` не находит ошибок;
3. проверьте, что изменения данных не затрагивают файлы вне `data/`;
4. после публикации убедитесь, что CI и GitHub Pages завершились успешно;
5. откройте публичный сайт и проверьте основной каталог.

Общие правила участия находятся в [CONTRIBUTING.md](../CONTRIBUTING.md), политика безопасности — в [SECURITY.md](../SECURITY.md).
